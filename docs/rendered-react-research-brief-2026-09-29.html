From design rules to rendered proof

A coding assistant can follow a design-system prompt and still ship the wrong color. The useful test is whether independent tools catch the source change, the built asset, and what the browser actually displays.

The enforcement path

The core principle: give assistants an explicit contract, then verify their output independently. The runtime rule engine is deterministic, read-only when checking, and has no model or network dependency.

Approved tokens→Source gate→Locked build→Browser probe

The project gate inventories files under a declared root, checks token-sheet parity, rejects uninspected source, and binds static JSX class names to directly imported, inspected CSS. The new fixture carries those exact inspected bytes into a fixed React build and permits only the expected source, runtime modules, and three output files.

What the browser proved

Chromium mounted one visible button, loaded the attested stylesheet, kept the approved token #2563eb, and computed the button background as rgb(37, 99, 235). The browser requested only the expected HTML, JavaScript, and CSS.

The red override changed only the served CSS response. Source files and on-disk build assets stayed unchanged. Separate negative checks caught a changed source byte, changed built CSS, and an extra emitted asset. Two builds from different local paths produced identical bytes.

What remains open

This is a rendered static component fixture. The HTML shell and React mount are trusted tool-owned code, so an ordinary app’s entrypoint, component graph, server, interactions, and full visual behavior are not yet covered. The new GitHub CI step is wired but has not been observed running remotely.

The next product test is a small protected pilot app: an assistant makes one approved design edit and one forbidden edit; CI must accept the first and reject the second while policy, verifier, and fingerprint remain independently controlled. That will measure the real problem: assistants staying inside the system as they edit application code.
