Keeping coding assistants inside the design system

Coding assistants can read a design system and still put unapproved colors or spacing into an app. This work turns the design rules into a source check across a declared project.

What the work established

Give the assistant a readable contract, then independently check the source it wrote. A prompt alone cannot prove that app code follows the approved system.

Approved tokens→Generated CSS + assistant context→Project source check→Reviewed handoff

The CSS policy binds tokens to allowed properties. adsys check reports source violations without editing files; it rejects literal drift, unknown variables, fallbacks, local token shadowing, and unsupported syntax. adsys fix makes exact repairs and rechecks them. Core enforcement is deterministic and offline.

What the project check adds

adsys project-check scans an explicit root, verifies the generated token stylesheet byte for byte, and inventories static HTML references. The fixture passes with two authored CSS files, 15 declarations, and one HTML file. Drift, stale tokens, inline styles, and a changed manifest fail the pinned check.

Every non-excluded file receives an outcome. CSS and HTML are inspected; exact contract files are trusted; unsupported formats fail as adapter-required. An opt-in TSX profile adds bounded source inspection.

Panel probes exposed HTML bypasses through <base>, duplicate links, token links hidden in inert markup, and empty class rules. These now fail. Each static HTML class must have a nonempty base rule in CSS directly linked by that page.

The new TSX boundary

The opt-in TSX profile uses the TypeScript Compiler API to inspect a static JSX component. It permits local CSS imports and one static function. Every literal className must resolve to an inspected, directly imported CSS rule; the token sheet must also be imported.

The panel reproduced three bypasses: @jsx factory replacement, amd-dependency injection, and a fake node on PATH. All now fail. The runner requires an explicit trusted Node binary and verifies parser bytes, sidecar hash, lock hash, and a fixed contract fingerprint before accepting the result.

Verification and research record

Local verification passed: 109 unit tests, nine normative cases, Ruff, mypy, three source-workflow verifiers, actionlint, and validate/check/fix/recheck. The invalid example's three errors are repaired; its accessibility warning remains. Remote CI has not run.

The separate research ledger records nine failed attempts and no valid finding. Each attempt was charged its reservation. The runner now reserves budget before starting Codex; the revised GitHub sequence has not been verified remotely.

Boundary and next decision

TSX passing means only that static component source met this narrow profile. React entrypoints, transitive imports, bundles, browser styles, runtime changes, semantics, and accessibility remain unverified. Next: close the app graph and inspect the built behavior in a browser.

Excluded files remain uninspected. The manifest, exclusions, hashes, fingerprint, and CI command need independent review. The optional parser currently installs in a source checkout; a wheel alone does not include node_modules.
